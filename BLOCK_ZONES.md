# Block Zones, Multi-RV Cycling & Evac — GALAXY EXPRESS

This extends the **existing** block model rather than adding a parallel one. The occupancy
authority is still `BlockSystem`; the N+1 gating still lives in `TrainSim`; the spline is still
`TrackPath`. The shipped scene is now the **GALAXY EXPRESS** layout: a 53-waypoint space coaster
with a chain lift, a vertical loop, a zero-g camel-back sector and two dedicated brake shelves,
built entirely by `SceneBuilder` (ParkShift → Build All Scenes).

## The shipped scene layout (5 blocks)

```
  [0] UNLOAD ─▶ [1] LOAD ─▶ [2] LIFT HILL ─▶ [3] LOOP + ZERO-G ─▶ [4] BRAKE RUN ──┐
    ▲   (station straight, z=2.2, x -6..6)      (drop → loop → camel-backs → MCBR)  │
    └───────────────────────────────────────────────────────────────────────────────┘
```

| Block | Name | Track it covers | Where a held RV stops (BrakePoint01 = 0.92) | Evac |
|------:|------|-----------------|---------------------------------------------|------|
| 0 | UNLOAD | Station straight, x −6..0 | Parks at block centre (x = −3) while unloading; gated stop lands on the flat station straight | Station platform itself |
| 1 | LOAD | Station straight, x 0..6 | Parks at block centre (x = +3) while boarding | Station platform itself |
| 2 | LIFT HILL | Pre-lift turn + chain lift (base ~(18.4, 13.5), crest ~(20, 41) at y ≈ 22) | Upper chain, ~4 m below the crest — the chain holds it | **Lift catwalk** (full-length walkway on the west side, handrails, stairs at the lift base) |
| 3 | LOOP + ZERO-G | First drop → vertical loop (top y ≈ 15.4, inverted) → rising banked turn → three zero-g camel-backs (z = 77.5) → high banked turn → **elevated mid-course brake run** (x ≈ −34, z 54→34, flat y 5.4) | On the MCBR shelf, ~z 47 | **EVAC PLATFORM B3** — deck alongside the MCBR at x ≈ −35.4 with handrails + stair flight to ground |
| 4 | BRAKE RUN | Diving turn home → **ground-level final brake run** (z = 2.2, x −12..−6, y 0.6) → station entry | On the final brake straight, x ≈ −10 | **EVAC PLATFORM B4** — at-grade deck beside the straight (x ≈ −13.8..−7.8) |

Ground muster: **EVAC ASSEMBLY POINT** pad + sign at (−17, 0, −0.5), beside the maintenance bay.

**Block boundaries are chosen so a gated RV always rests on plausible track** — station straight,
lift chain, or a flat brake shelf; never mid-loop and never on a camel-back. Boundaries live in
`TrackPath.BlockStarts` (normalized arc positions) and are **computed at build time** by
`SceneBuilder`: with `BlockStarts` empty and `BlockCount` = waypoint count, `DistanceOf(i, 0)`
yields each waypoint's exact arc distance, so boundary waypoints {0, 4, 8, 17, 45} are snapped
without hand-integrating the spline. Rebuilding the scene recomputes everything.

## Speed multipliers

The scene has no `SimConfigSO` asset assigned, so `AttractionManager.Awake` supplies the
split-station defaults `{1, 1, 1.7, 1.15, 0.6}` = Unload, Load, Lift (fast chain), Course,
Brake run. These still map 1:1 onto the new blocks. Block 3 is much longer than before, so if
its visual speed feels too high, create a `ParkShift/Sim Config` asset (BlockCount 5,
SeparateLoadUnload on, TrainCount 2, multipliers e.g. `{1, 1, 1.7, 0.85, 0.6}`) and assign it to
`AttractionManager.ConfigAsset` — note that bypasses the built-in Solo/Coop tuning split.

**N+1 rule:** N RVs need at least N+1 blocks. With 5 blocks the shipped **2 RVs cycle cleanly**;
a 3rd (HMI "Add RV") creates deliberate stacking pressure feeding the brake run.

## Loop framing (why the track doesn't flip)

`TrackPath.FrameAtDistance` uses `LookRotation(fwd, Vector3.up)`, which flips 180° through a
vertical loop. The track mesh therefore samples `TrackMeshBuilder.FrameTable` — a
parallel-transport frame table that carries the up-vector through the inversion, feathers the
seam residual around the lap, and layers the (±44°, scene value) curvature banking back on for
flat-ish turns only. `FrameTable` is public and runtime-safe: **`TrainVisual` still uses
`Path.FrameAtDistance` and will visibly flip at the loop top until it's switched to a
`FrameTable`** (owner: train/guests agent).

## Tuning (all in the inspector)

On a `ParkShift/Sim Config` asset (optional, see above): `BlockCount` / `TrainCount`,
`BlockSpeedMultipliers`, `SmoothMotion`, `BrakePoint01` (0.92 — keep matched to
`TrackPath.BrakePoint01`), `BrakeDecel`, `LaunchAccel`.

On the **`TrackPath`** component: `BlockStarts` / `BlockLabels` (regenerated by SceneBuilder —
edit the `boundaryWp` array in `SceneBuilder` instead so rebuilds keep your change),
`MaxBankDegrees` (44 in this layout), `BrakePoint01`.

Gizmo legend: each block is a colored ribbon along the spline, a vertical post + sphere marks its
start boundary, and a short **red** line marks the brake point.

## Verification

`_previews/verify_blocks.py` ports the gating/easing math (no Unity needed) and confirms
coast-to-stop lands exactly on `BrakePoint01` and the N+1 safety invariant. It is
layout-agnostic (works in block-progress space), so it still applies to the 5-block scene.

The default `SimConfig` (`SmoothMotion=false`, 4 blocks, 2 RVs) keeps the legacy instant-motion
path and the original staging, so the existing 17 headless core tests are unaffected — the
GALAXY EXPRESS changes are entirely scene-side (SceneBuilder / TrackPath data / TrackMeshBuilder
visuals).
